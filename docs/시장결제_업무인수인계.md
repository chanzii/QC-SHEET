# 시장결제 자료 제작 업무 인수인계

이 문서는 업무툴의 **시장결제 자료 제작** 기능만 다룹니다. QC시트 생성기와 발주서 도장은 각각의 코드와 별도 인수인계 자료를 확인하세요.

## 작업 시작 전

- GitHub 저장소 `chanzii/QC-SHEET`의 **현재 기본 브랜치와 실제 배포 상태를 먼저 확인**합니다. 로컬 복사본이나 이 문서의 설명이 최신이라는 보장은 없습니다.
- `main`에는 QC 업무 파일의 업로드·삭제도 기록될 수 있습니다. 최신 변경을 확인하고 필요한 파일만 수정하며, 다른 업무툴과 업무 파일을 덮어쓰지 마세요.
- 이 저장소는 확인 시점에 공개 저장소입니다. 실제 영수증, ERP 데이터, 결제금액, 개인정보, 토큰을 저장소·테스트 픽스처·로그에 올리지 마세요. 테스트에는 가상의 데이터를 사용합니다.
- 사용자는 기존 화면에서 이어서 개선하는 방식을 선호합니다. 변경 요청이 개별작업인지 다중작업인지 확인하고 지정된 범위에 적용하세요.

## 구성과 배포

- `static/market_single.html`: 개별작업. HTML, CSS, JavaScript가 한 파일에 들어 있습니다.
- `static/market_batch.html`: 다중작업. 역시 독립 HTML입니다.
- `qc_sheet_app.py`: Streamlit 진입점과 업무툴 사이드바. QC시트 UI는 `qc_sheet/ui.py`에 있습니다.
- `.streamlit/config.toml`: Streamlit 정적 파일 제공 설정.
- 운영 앱은 Streamlit Community Cloud의 기존 업무툴입니다. Streamlit 화면에서 시장결제로 이동할 때 링크는 `app/static/market_single.html` 같은 **상대 경로**를 사용합니다. 과거 절대 경로 `/app/static/...`로 바꾸었다가 프록시 경로를 벗어나 무한 로딩이 발생했습니다. 경로와 복귀 링크는 실제 배포 환경에서 확인하세요.
- 메뉴는 하나의 공통 모듈로 관리되지 않습니다. 사이드바를 변경할 때 관련 화면의 메뉴와 링크를 각각 확인하세요.
- 시장결제는 각 사용자 브라우저에서 처리하고 결과물을 각자의 PC에 저장하는 설계입니다. QC시트의 GitHub 업로드·동기화 함수에 영수증이나 시장결제 데이터를 연결하지 마세요. 배포 후 실제 네트워크 요청과 사용자 간 분리도 검증해야 합니다.
- 담당자명은 브라우저의 `localStorage` 키 `market_payment_owner`에 저장됩니다. 같은 브라우저 프로필의 개별·다중작업에서 사용하는 구성입니다. 브라우저 저장 데이터 삭제, 다른 PC·프로필, 배포 경로 등에 따른 동작은 실제 환경에서 확인하세요.

## 업무 흐름과 표시 규칙

ERP에서 엑셀을 내려받아 헤더를 제외한 데이터 행을 복사하고, 개별 또는 다중작업에 붙여넣어 적용합니다. 영수증 이미지는 파일 선택, 끌어놓기 또는 붙여넣기로 넣고, 왼쪽에 영수증, 오른쪽에 결재란과 내용을 표시합니다. 자동 입력값도 수정할 수 있습니다.

- 세금계산서: 전자 / 수기. 기본은 전자.
- 작업 상태: 선택 또는 추가. 자주 쓰는 예시는 출고 전, 출고 후, 작업 전, 입고완료. 추가 상태의 영구 저장 여부는 구현과 실제 동작을 확인하세요.
- 결제 비율: 100%, 50% 선택 또는 0~100 직접 입력. 작업 상태나 결제 비율이 없으면 결과물 위쪽에 빨간색 `필수 선택항목이 누락되었습니다`를 표시합니다.
- 스타일 번호: 중복을 제거하여 1~2개는 `/`로 구분합니다. 3개 이상이면 첫 스타일과 `외 N건`을 표시합니다. 입력값에는 전체 스타일을 유지합니다.
- 수량: ERP 입고수량을 결제수량으로 사용합니다. 발주량·출고량 미입력 시 `결제·발주 동일`을 표시하고, 차이가 있는 자재의 발주량·출고량만 입력할 수 있습니다. 여러 자재의 입력칸을 처음부터 모두 펼치지 않습니다. 수량 차이가 있으면 결과물에서 자재명을 먼저 표시하고 결제·발주·출고를 각각 별도 줄로 표시합니다.
- 자재비: 공급가액·부가세·합계를 표시하고, ERP의 정산금액/결재금액은 별도로 가져옵니다. 서로 다를 수 있으므로 임의로 같은 값이라고 가정하지 마세요.
- 운임비: 자재비와 같은 결과물에 별도 항목으로 표시합니다. 현재 구현은 `부가세 포함` 선택 시 입력한 공급가액의 10%를 반올림해 부가세를 구하고 합산합니다. `부가세 미포함` 선택 시 입력 금액을 합계로 사용합니다. 회계상의 다른 의미를 추정해 계산을 바꾸지 말고 사용자와 확인하세요.
- 특이사항은 결과물에서 크고 굵은 빨간 글씨로 표시합니다.
- 결과물 아래 정산번호 연번은 마지막 하이픈 뒤 숫자에서 앞의 0을 제거합니다. 인쇄 시 오른쪽·아래쪽 여백은 각각 8mm로 설정돼 있습니다.
- 결재란의 생산부 담당 칸에는 입력한 담당자명을 표시합니다. 이 표시 자체를 전자 승인이나 실제 결재 완료로 해석하지 마세요.

## 엑셀 형식

개별작업은 아래 두 형식을 **열 개수와 고정 위치**로 구분합니다. 헤더를 제외하고 표시한 범위 전체를 복사해야 합니다. 비어 있는 셀도 열 위치가 유지돼야 합니다. 코드의 실제 열 순서와 오류 처리부터 다시 확인하세요.

1. 현재 정산 양식: 21열
   `선택, 거래처명, 정산일자, 자재구분명, 자재코드, 자재명, 자재색상, 품번, 차수, 작지발주번호, 작지색상, 입고수량, 입고단가, 입고금액, VAT, 클레임금액, 입고지연일, 정산금액, 잔액, 정산번호, 비고`
2. 이전 입고 양식: 22열
   `선택, 거래처명, 자재구분명, 자재코드, 자재명, 자재색상, 품번, 차수, 작지발주번호, 작지색상, 입고일자, 입고수량, 입고단가, 입고금액, VAT, 입고금액(V), 입고지연일, 클레임금액, 결재금액, 잔액, 입고번호, 비고`

개별작업의 이전 양식은 `입고금액(V)`을 합계로 가져옵니다. `입고번호`는 정산번호가 아니므로 정산 연번으로 표시하지 않습니다. 현재 정산 양식은 입고금액과 VAT의 합으로 자재비 합계를 계산합니다.

다중작업은 확인 시점에 **현재 21열 정산 양식만** 지원합니다. 정산번호가 같은 행을 한 건으로 묶고, 건별로 이미지를 넣고 선택 항목을 입력합니다. 서로 다른 스타일이나 자재도 한 건에 들어갈 수 있습니다. 붙여넣은 건을 개별 삭제할 수 있습니다. 다른 양식 지원을 다중작업에 임의로 확대하지 마세요.

클레임금액과 입고지연일은 현재 시장결제 금액 계산에 사용하지 않습니다. 사용자는 클레임금액 처리를 나중에 별도로 정하기로 했습니다. 품번이 비어 있는 행은 임의로 추정하지 말고 확인 표시를 유지하세요.

## 저장과 검증

- PDF 저장은 브라우저 인쇄 창을 사용합니다. A4 가로를 기준으로 하며 개별작업은 `window.print()`, 다중작업은 개별 또는 전체 인쇄를 사용합니다.
- PNG/JPG는 브라우저의 Canvas에서 생성합니다. 다중작업에는 개별 저장과 ZIP 일괄 저장이 있습니다.
- 화면 미리보기의 DOM/CSS와 PNG/JPG용 Canvas 그리기는 별도 구현입니다. 배치나 문구를 수정하면 **미리보기, PDF/인쇄, PNG, JPG, 다중 ZIP**에 각각 반영됐는지 확인하세요.
- 실제 영수증과 결제 데이터 없이 가상 데이터로 두 엑셀 형식의 열 구분, 합산, 수량 예외, 입력값 수정, 담당자명, 누락 경고, 연번, 인쇄와 이미지 저장을 검증합니다. 다중작업은 같은 정산번호의 여러 행, 서로 다른 정산번호의 분리, 개별 삭제와 일괄 저장을 확인합니다.
- 인쇄는 프린터의 실제 출력 가능 여백에 영향을 받습니다. A4 미리보기뿐 아니라 사용 프린터에서 번호와 내용이 잘리지 않는지도 확인해야 합니다.
- 배포 후 실제 앱에서 메뉴 이동, 최신 파일 반영, 두 브라우저 세션의 작업 분리, 업무 데이터가 서버/GitHub로 전송되지 않는지 검증합니다. 코드 정적 검사만으로 실제 배포 동작을 확인했다고 보고하지 마세요.

## 현재 미구현·주의사항

- 한 결제 건에 여러 장의 영수증을 넣는 기능은 아직 구현하지 않았습니다. 사용자는 필요할 때 다시 요청하겠다고 했습니다. 논의된 방향은 첫 페이지에만 결제 내용과 결재란을 두고, 이후 페이지에는 추가 영수증만 배치하는 것입니다. 사용자 재요청 없이 구현 여부를 단정하지 마세요.
- 영수증 PDF를 직접 첨부하는 기능은 현재 안내상 지원하지 않으며 이미지를 사용합니다.
- 작업 중인 내용을 서버나 GitHub에 저장하지 않는 방향이므로 새로고침·페이지 이동 시 작성 내용이 사라질 수 있습니다. 새 동작을 추가할 때 사용자별 분리와 데이터 유실 방지를 함께 검토하세요.
- 이 문서는 확인 시점의 코드와 대화 내용을 정리한 것입니다. 배포 상태, 실제 브라우저·프린터 결과, 회사 내부 결재 기준은 문서만으로 확인된 것이 아닙니다.
